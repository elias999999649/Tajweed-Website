# Technical SEO audit checklist

This checklist protects crawlability, relevance, helpfulness, and technical quality. It does not promise rankings.

## Before publishing a route

- [ ] The page has one useful semantic H1.
- [ ] The title is unique, descriptive, and written for people.
- [ ] The meta description accurately summarizes visible page content.
- [ ] The URL is lowercase, stable, descriptive, and free of unnecessary parameters.
- [ ] The page has one canonical URL derived from `NEXT_PUBLIC_SITE_URL`.
- [ ] Open Graph and Twitter metadata describe the same visible page.
- [ ] Any image has descriptive alt text; decorative images use empty alt text.
- [ ] Headings form a logical H1 → H2 → H3 hierarchy.
- [ ] The page is reachable through normal HTML links.
- [ ] Breadcrumbs describe the learner's path and match visible content.
- [ ] Internal links use descriptive anchor text and point to canonical URLs.
- [ ] The page has enough unique, useful content to justify indexing.
- [ ] Quran text, references, translations, audio, and Tajweed claims have completed qualified review.

## Structured data

- [ ] Organization and WebSite data appear only where they describe the site.
- [ ] BreadcrumbList matches the visible breadcrumb trail.
- [ ] Article or LearningResource data describes visible page content.
- [ ] FAQ structured data is added only when visible FAQs are genuine and useful.
- [ ] Structured data is validated before release.
- [ ] No generated citation, author, review, rating, or FAQ is presented as authoritative without evidence.

## Crawl and index controls

- [ ] `/robots.txt` is reachable and references `/sitemap.xml`.
- [ ] `/sitemap.xml` contains absolute canonical URLs only.
- [ ] New published rules are automatically added to the sitemap through the taxonomy.
- [ ] Draft, review-only, and duplicate content are excluded from the sitemap.
- [ ] Search-result pages use `noindex,follow`; they are not blocked in robots.txt.
- [ ] API, internal, and application-only routes are not indexable.
- [ ] 404 pages return a real 404 status.
- [ ] Slug changes have permanent redirects.
- [ ] There is one preferred host and HTTPS is enforced at the hosting layer.

## Quality and performance

- [ ] Important content is present in server-rendered HTML.
- [ ] The site works with JavaScript disabled for reading and navigation.
- [ ] Arabic text has correct `lang="ar"`, `dir="rtl"`, contrast, and readable sizing.
- [ ] Keyboard navigation and focus states work throughout.
- [ ] No content is hidden solely for search engines.
- [ ] Lighthouse and Core Web Vitals are checked on representative mobile pages.
- [ ] Search Console validates sitemap processing and inspected URLs after deployment.
- [ ] Broken links, canonical mismatches, duplicate titles, and missing descriptions are checked in CI.
